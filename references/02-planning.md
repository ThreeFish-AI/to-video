# Stage ② 策划案生成（skill 规格 · 02）

> Stage ②：基于 Stage ① 事实源（A paper-notes / B source-notes / C gl-notes，型别判定见 [01](./01-source-extraction.md)）产出 `script/planning.md`——全片的叙事与视觉蓝图。

## 产出结构（六节）

1. **定位表**：平台（B 站/YouTube 中长视频）、时长目标（硬约束区间）、形态（AI 配音 + 代码动画，无真人）、受众（不预设 ML 背景的普通人）、核心内容范围（论文章节取舍）。
2. **叙事策略**：
   - **视觉母题全片统摄 + 局部类比按难点准入**（对齐 guided-learn 类比四硬律）：全片的连续感由**视觉母题（恒定几何锚点、色彩语义契约、空间构图）**统摄，**严禁把局部口播类比升格为贯穿全片的剧场或世界观**；C 型信源直接**一物一喻继承** `gl-notes.md` 已核准的局部类比与失配拦截句（1–3 句点亮直觉即切回机制画面，零类比直讲合法），不私自另造新喻；
   - **开篇钩子（Hook）顶层设计（地位高于视频标题）**：视频前 3–5 秒决定完播率，开篇入场的抓人表述重要性高于视频标题。全片开篇必须以**「这是 XXX ……」**句式模式破题入场；开头内容必须充分吸引人、第一时间留住观众（制造认知反差、危机痛点或强烈好奇），且开头讲述的「这是 XXX」**必须与接下来要讲述的内容主干或核心机制强关联**（严禁噱头式脱节），正好抛出一个接下来要讲的核心内容的精准引子；
   - **人机协同钩子候选矩阵（策划期必出）**：策划案必须慎重设计开篇，**显式提供 3–5 个不同维度的优质备选 Hook**（如：反直觉颠覆型、极致危机/痛点型、新范式/新物种揭示型、悬念冲突型），逐一阐明：① 钩子文本（「这是 XXX ……」）、② 吸引力留存逻辑、③ 核心主干关联锚点、④ 抛出的核心引子，**交给人（创作者）自主评估与挑选决策**；选定项在矩阵中显式标记「★ 选定」+ 一句理由，落盘 planning.md（无人工介入的会话由 agent 定推荐项并标注「自动选定（待人工复核）」），定稿后作为 Stage ③ 逐字稿 P0 幕首句的执行基准；
   - 一条主线问题（钩子 → 悬念 → 回答，由开篇 Hook 引子自然展开）；
   - 记忆点节奏（约每 60–90 秒一个，全部取自事实源素材库：A 型 paper-notes 第 4 段；B 型 source-notes 叙事正文（B 轨）；C 型对应 01 §七「素材映射」）；
   - 理性收尾原则（不贩卖焦虑，把悬念留在开放问题上）。
3. **视觉语言**：
   - **色彩语义契约**：为本集核心概念分配专属色（如上集 蓝=改大脑/橙=改装备）；任何示意图严格用色；
   - 深色底 `#0E1116` 系、警示红 `#FF5C5C`、确认绿 `#7ED321`、金句卡衬线体；
   - 公式只作画面角标彩蛋，不进口播主线；
   - 设计视觉锚点与比喻母题前先读 [建模手册](MODELING-PLAYBOOK.md)（跨集已验证的建模方法与反模式，定式优先）。
4. **分幕结构表**：幕号 | 目标时间 | 主题 | 叙事要点（回溯事实源）| 视觉锚点。通常 6–7 幕。
5. **生产管线图**（Mermaid）：文档层→配音层→视觉层，标注单一事实源节点。
6. **边界与不做的事**：BGM 留空轨、论文外观点不进口播、许可注意。

## 纪律

- 每个叙事要点须指向事实源的具体小节；
- 过 ④ 后按 [⑤ 成文优化](./05-prose-refinement.md) 第五节改写成文（节内结论先行、小标题写成判断句、不做的事写出立场）；六节节名不动。
- 取舍原则：深度 > 广度，砍掉的章节在收尾「一句话带过」而不是硬塞；**宁砍旁支章节广度，绝不砍保留机制的「具体输入走查实例（Worked Example）」与「破坏性实验反例」**（被动收看视频无法回翻，删掉具体走查过程只留抽象规则会让外行观众当场掉线）；
- 时长预算：新集默认按 **254 字/分钟**（story 终声档口径，`config.STYLE_CHARS_PER_MIN`；非 story 档 280）；
  各幕目标时间是规划值，最终以配音实测为准。
  ★ **该口径不是纯语速，而是含停顿的等效口径** —— EP1 实测反推（sunny-steady 280 口径）：187 句 / 3884 字
  → 成片 14:01，其中纯语音 773 s（**301 字/分**），句间/幕间停顿 + 片头尾静默另占 68 s。两者恰好抵消，
  故 `字数 ÷ 口径` 对**全片时长**的估算误差仅约 1%（story 档 254 系 RSI-021 五集整集实测）。实践推论：
  1. **字数是硬约束，句数不是** —— 合并短句能省停顿开销，但省不了字数；要压时长必须真删内容。
     （本集教训：把 263 句合并到 229 句，字数只从 5054 掉到 4909，时长几乎没动。）
  2. 反过来推容量：`目标分钟 × 254 ≈ 可用字数`（14 分钟 ≈ 3560 字）。
  3. 句均 20–24 字时，句数 ≈ 可用字数 ÷ 句均（14 分钟约 148–178 句）。
  4. TTS 成本与句长反相关（短句 RTF 最差），故在字幕可读上限内（≤35 字）**宁长勿短**。
