# Stage ① 信源精读取证（skill 规格 · 01）

> Stage ①：把信源转化为科普视频的**单一事实源**。本文件是提取代理的提示词规格，
> 可直接作为 Workflow 子代理 prompt 底稿。
>
> **三类信源，纪律不同**：
>
> | 型 | 信源形态 | 事实源文件 | 取证工具 | 核心风险 |
> |---|---|---|---|---|
> | **A** | 论文 / 综述 PDF（冻结、可逐字回溯） | `research/paper-notes.md` | `paper_extract.py` | 断言引申超出原文 |
> | **B** | 在线文档 / 课程站点 / 代码仓库（**会变**） | `research/source-notes.md` | `source_ledger.py` | 陈旧、口径不可复算、把他人的分析当作既成事实 |
> | **C** | guided-learn 精读产物《{学习目标} 精读与通俗拆解》（本地冻结 markdown） | `research/gl-notes.md` | 冻结快照 + `paper_extract.py` find / `source_ledger.py` 按需穿透 | 二手转述失真（通俗化引入的偏差与遗漏）、鲜度过期 |
>
> A 型见下方正文；B 型与 C 型的增量纪律分别见「B 型信源」「C 型信源」两节。**三型共用的地基是同一条**：
> 口播的每一条断言都必须能回溯到事实源文件的某一节，回溯不到的不得进入逐字稿。

**目录**：A 型（论文）：输入 · 每章代理任务 · 纪律 · 汇编与验收 · 官方工程站点信源补充 ｜ B 型（文档 / 代码 / 站点）：与 A 型的根本差异 · 一、双轨取证 · 二、证据三级 · 三、数字纪律 · 四、二次信源的分歧清单 · 五、图片纪律 · 六、验收 ｜ C 型（guided-learn 精读产物）：定位 · 一、冻结快照 · 二、锚点回溯 · 三、穿透抽查 · 四、证据定级 · 五、增量补证 · 六、鲜度登记 · 七、素材映射 · 八、验收 ｜ 多章批量取证

## 输入

- 论文 PDF 绝对路径（或 HTML 版 URL）。
- 分章清单（每章一个代理，并行执行；章的粒度以「一个代理能在一次上下文内精读完」为准，长综述通常 8–10 章）。
- 论文配套**官方工程站点/仓库** URL（如有；由使用者提供或从论文正文/文末资源链接发掘）。

## 每章代理任务

通读所辖章节全文（不是摘要、不是跳读），按以下**四段式结构**输出：

### 1. 章节主旨综述段（中文，300–600 字）
- 本章解决什么问题、在全文中的位置、组织逻辑（作者按什么维度切分小节）。
- 形式化定义原样摘录（符号 + 一句话白话解释）。

### 2. 代表方法列表
每个方法一条：`- **名称（作者，年份）**：机制一句话（通俗但准确）。（例：论文原文表述 "..."）`
- 覆盖正文与表格点名的方法；表格-only 方法单独分组标注。
- 机制描述必须落在论文原文的动词与对象上，不自行引申。

### 3. 风险 / 挑战 / 防护
- 论文明确列出的失败模式、trade-off、防护措施；保留关键英文术语。

### 4. 科普叙事素材（金句 / 比喻 / 例子）
- 每条：【标签】英文原句（如有）→ 中文白话 → 画面感建议。
- 优先收录：反直觉断言、具体数字、有名字的系统、作者自评的边界句。
- 这一段是后续逐字稿「记忆点」的原料库，宁多勿漏。

## 纪律（硬约束）

1. **零编造**：每条内容须能回溯到论文原文；不确定的写「论文未展开」。
2. 引用编号/图表号原样保留（如 Figure 4、Table 3），便于校验。
3. 不做价值判断、不添加论文之外的观点。
4. 英文原句须逐字精确（供字幕角标与事实核查复用）。

## 汇编与验收

- 主代理合并各章产出 → 头部补：来源（IEEE 引用）、作者/机构、提取方式与日期、与仓库既有调研报告的交叉引用。
- 一致性复核：跨章术语统一（同一概念不出现两种译名）、编号连续、重复方法去重。
- 验收：抽 10 条断言 grep 原文验证命中；无命中项打回重查。
- 过 ④ 后按 [⑤ 成文优化](./05-prose-refinement.md) 第六节整理成文（主旨段结论先行、断言按问题分组）；英文原句、图表号与 § 锚点一律不动。

## 官方工程站点信源补充（Stage ① 可选扩展）

论文配套官方站点（项目主页 / Awesome 仓库配套页）常含论文之外的增量事实：收录统计、代表性方法清单、章节地图、评测协议图解。提取时遵守：

1. **只收录事实性内容**（数字、清单、定位声明、图的概念说明），逐字引用原文表述，标注 URL 与访问日期；不收录社区评论/PR 讨论等非权威内容。
2. 产出统一落在 `paper-notes.md` 末尾独立的「信源补充」大节，每条显式标注 `（来源：官方工程站点，非论文正文）`，与论文正文提取内容物理隔离——后续逐字稿回溯断言时可区分证据等级。
3. **严禁下载或嵌入站点图片素材**（版权风险 + 与代码动画美学不一致）：站点图表只转为**文字规格**（节点/流向/分区语义描述）供 Remotion 场景重建。
4. 站点信源**单集专属**：只服务于本集论文的补充，不跨集引用（各集主线互相独立，防串线）。
5. 站点数字若与论文正文冲突，以论文为准并注明差异。

# B 型信源 · 文档 / 代码 / 课程站点

> 首次实践：[claude-code-explained-video](https://github.com/ThreeFish-AI/negentropy/blob/master/apps/negentropy-influence/episodes/claude-code-explained-video/research/source-notes.md)
> （课程站点 4 页 + 代码仓库 @ 固定提交）。产出文件名用 `research/source-notes.md`
> 以区别于 A 型的 `paper-notes.md`。

## 与 A 型的根本差异

论文是冻结的，站点和仓库是活的。**逐字稿在录完音之后就冻住了，而信源还在动** —— 这就是
[ISSUE-162](https://github.com/ThreeFish-AI/negentropy/blob/master/docs/.agents/issue.md) 的成因。B 型的全部增量纪律都从这一条推出。

## 一、双轨取证（缺一不可）

| 轨 | 取什么 | 怎么取 | 用途 |
|---|---|---|---|
| **A 轨 · 可核验原文** | 代码仓库文件 | `raw.githubusercontent.com/<owner>/<repo>/<**commit sha**>/<path>` | 代码逐字、数字实测 |
| **B 轨 · 叙事正文** | 站点页面 | 页面文本；数字须来自**水合后 DOM** 或数据端点 | 叙事框架、表格、图解文案 |

**A 轨的 URL 必须是不可变引用**（含 commit sha，不能写分支名）——`source_ledger.py` 会校验
`--pinned-ref` 出现在 URL 中，并在 `verify` 时把 raw 指纹漂移判为 **FAIL**（说明取证链失效）。
B 轨只比对**剥标签归一后的正文**指纹，漂移报 **WARN**（去复核笔记），因为构建产物哈希天天变。

```bash
uv run --no-project $T/scripts/source_ledger.py --project $P fetch --name s01-code --kind repo \
    --pinned-ref <sha> --via "pinned commit, MIT" --url https://raw.githubusercontent.com/o/r/<sha>/f.py
uv run --no-project $T/scripts/source_ledger.py --project $P fetch --name s01-site --kind site \
    --via "SSG 预渲染" --url https://example.com/zh/s01/
uv run --no-project $T/scripts/source_ledger.py --project $P verify    # 交付前必跑
```

## 二、证据三级（B 型的核心发明，必须写进事实源头部）

| 级 | 含义 | 口播允许的表述 |
|---|---|---|
| 【一】 | 仓库文件实测（可复算） | 可直接断言 |
| 【二】 | 站点正文 | 可断言，属「课程/文档的讲法」 |
| 【三】 | **他人对闭源产品源码的分析** | **必须**带归属句（「作者拆过源码，他说…」），**不得**说成产品既成事实 |

三级证据往往是全片信息量最大的部分，也最容易说错。落法：
1. 事实源里逐条标级；
2. 逐字稿里三级断言**前 3 句内必须出现归属语**（可机械检查）；
3. 画面角标同步压「（某人的）源码分析」。

## 三、数字纪律

1. **口径必须可复算**：引用行数/数量前，自己在固定提交上量一遍（`wc -l` 与「非空非注释」是两个
   不同口径，必须说明用的哪个）。
2. **复算不出就不用**：站点标注的数字若与固定提交上任何口径都不吻合，判定为「早期提交的遗留值」，
   写入分歧清单，**口播改说趋势**（「从一百多行长到两百多行」），画面给实测值 + 口径 + 取数日期。
3. **活数据不进口播**：star 数、总章数、榜单排名——说死必陈旧。
4. 页面数字不取自未水合 HTML（ISSUE-162 的原始教训）；SSG 站点可先验证「数字同时出现在可见
   文本与框架载荷中」，成立则 HTML 文本即渲染结果。

## 四、二次信源的分歧清单（必备一节）

站点与仓库会漂移（改版节奏不同）。事实源必须有一节**分歧清单**，逐条记：分歧点 / 两轨各自的说法 /
处置。常见类型：编号漂移、示例代码新旧、总量不一致、结论已被上游修正。
**处置默认取更可核验的一轨**（通常是仓库），并在笔记里留下取证链——不要偷偷改掉，
它是「过程规则为什么存在」的物证。

## 五、图片纪律（与 A 型一致，从严）

**严禁下载或嵌入站点/仓库的图片素材**（版权 + 与代码动画美学不一致）。站点图表与交互式演示
只转**文字规格**（节点 / 流向 / 分区 / 帧文案）供 Remotion 重建 —— 重建**信息结构**，
不复刻美术（配色构图动效一律用本集视觉契约）。

## 六、验收

- `source_ledger.py verify` FAIL 0（B 轨 WARN 需人工确认笔记仍成立）。
- 抽 10 条断言回溯到事实源命中；其中至少 3 条是【三级】，逐条确认逐字稿里有归属句。
- 分歧清单非空（真实项目几乎不可能零分歧；为空说明取证不够细）。
- 所有数字都能在固定提交上复算，且口径已写明。

# C 型信源 · guided-learn 精读产物

> guided-learn（下称 GL）的《{学习目标} 精读与通俗拆解》是**已被整理过的二手信源**——它替本集
> 完成了通读与通俗化，但**不免除取证义务**。C 型 = 把 GL 产物冻结为本集事实源正文
> （`research/gl-notes.md`），回溯链经它上溯到原始信源；GL 产物内引用的原始信源是**指针**，
> 不是第二本笔记。

## 一、冻结快照

- GL 产物复制落 `research/gl-notes.md`——本集唯一的事实源正文文件。
- 头部登记：GL 产物生成日期 + **原始信源清单**（逐条：A/B 型、URL 或本地路径、GL 取数日期）；
  可得的原始文件（PDF 等）登记归档路径，供穿透抽查。

## 二、锚点回溯（一级）

- 口播断言回溯 gl-notes.md 小节（全貌解剖 / 机制章 / 五大规律 / 核心争议 / 批判性边界——
  GL 产物的既有章节形态）。
- gl-notes 关键断言带原始信源指针，使回溯链可继续上溯；只锚到 GL 产物而拿不出指针的断言
  按无锚处理。
- **一集只维护 gl-notes 一本笔记**：GL 产物引用的活信源指纹登 `research/sources.toml`
  （沿用 B 型机制），不开第二本 source-notes。

## 三、穿透抽查（二级，数字与高危断言必做）

- 数字、日期、对比、因果、归属类断言**不得止步于 GL 产物**：A 型原始 PDF 用
  `paper_extract.py find` 定点回查；B 型 URL 按 `source_ledger.py` 纪律 pin 后核。
- 口径沿 ④ 验收：**全部数字断言穿透 + 非数字断言抽 10 条**。
- 穿透不中的断言要么降级表述（归属句 / 趋势化，沿用 B 型三级纪律），要么走「五、增量补证」。

## 四、证据定级

- GL 产物对原始信源的转述按 B 型三级**≤ 二级**处理；GL 内置实测日志本集不复算即按转述计
  （本集复算了可升）；三级断言的归属句纪律沿用。

## 五、增量补证

- 视频需要而 GL 未覆盖的内容，追加进 gl-notes.md 末尾「信源补充」节（沿 A 型官方站点补充的
  既有形态），每条标一手出处；**不回写 GL 原产物**。

## 六、鲜度登记

- 头部取数日期即事实源鲜度；「活数据不进口播」纪律沿用；口径敏感的活信源按 B 型
  `verify` 执法（FAIL 0）。

## 七、素材映射

- GL 的白话主线、类比与规律 PREP 叙事 = ② 记忆点节奏的原料库等价物（对应 A 型每章四段式的
  第 4 段）；取证时不重写 GL 的白话，穿透核其事实面即可。

## 八、验收

- 抽 10 条断言回溯 gl-notes 命中；数字断言穿透原始信源全中；活源台账 `verify` FAIL 0。

## 多章批量取证（多集系列 / 多章一集）

> 规格落地：[source-map/](https://github.com/ThreeFish-AI/negentropy/blob/master/apps/negentropy-influence/source-map/)（首例 [claude-code-explained](https://github.com/ThreeFish-AI/negentropy/blob/master/apps/negentropy-influence/source-map/claude-code-explained.md)；工作区落点 `$W/source-map/`）。
> 适用：一个系列吃同一信源的多章（如课程站点 + 仓库），或一集吃 ≥3 章。

1. **章节→集归属、钉选（pinnedRef）、README 文件名（随修订变）只在系列级 `source-map/<series-id>.toml` 登记一次**；
   人读版 `.md` 讲清为什么（含修订分叉叙事）。各集 `source-notes.md` **只链接、永不重述**——
   重述即第二事实源，两轨章号错位时必然漂移（ISSUE-165 的教训上探一层：站点与仓库的切分
   本来就不是同一时刻的产物，散文与代码的新鲜度要分别评估之外，还要评估**切分本身**的年龄）。
2. **台账条目由 `sync` 从地图派生、不手写**（`{slug}-readme` / `{slug}-code` / `{slug}-site`，
   多 sitePath 时 `{slug}-site-{path}`）——与既有交付集的字节兼容，防命名漂移：
   ```bash
   uv run --no-project $T/scripts/source_ledger.py --project $P sync  --map $W/source-map/<sid>.toml --episode N [--dry-run] [--refetch]
   uv run --no-project $T/scripts/source_ledger.py --project $P audit --map $W/source-map/<sid>.toml --episode N   # 离线，无网络
   ```
   `audit` 三断言：条目齐 / 无跨集混入（防证据串集）/ repo 条目 `pinned_ref` = 地图钉值。
3. **钉在未合并分支时**（raw URL 随分支强推/删除而失效，verify 会 FAIL 兜底）：台账已登记
   raw_sha256 全指纹；另把取证字节归档至各集 `research/source-archive/<pin 前 7 位>/`
   （归档文件用 `.md.txt`/`.py` 后缀，避免第三方原文里的相对链接被 check_series 规则 5 误判）。
4. **归档即分发，许可声明必须随副本落地**：`source-archive/` 下放的是上游整文件级字节副本
   （本系列单文件逾两千行），属各主流开源许可所称的「实质性部分」——MIT/BSD/Apache 都要求
   副本附带版权与许可声明。故每个建了归档的集，其 `research/source-archive/` 下须有：
   - `LICENSE`——上游**同一固定提交**下许可文件的字节副本（连同 sha256 记录在旁，
     日后可复核取的是哪一版）；
   - `README.md`——出处表（上游项目 / 仓库 URL / 许可 / 固定提交 / 取数日期 / 指纹台账位置），
     章节归属只链接系列地图、不重述。

   **这是单一事实源纪律的显式例外，且是唯一一处**：各集工程目录是可被单独取出、单独交付的
   单位，声明收敛到系列级一处，取出单集时就会丢。归档之外的一切出处信息仍只登记在系列地图。
   上游无许可文件或许可不允许再分发时，**不建归档**——只留台账指纹，改在 source-notes 里
   记明「原文不可归档」的理由。
5. 验收追加：`audit` 离线零报警 + `verify` FAIL 0 之外，地图本身的形状由
   `tests/test_source_map.py` 执法（pin 覆盖、slug 唯一、派生名全局不撞等）；
   建了归档的集另核 `source-archive/{LICENSE,README.md}` 二者齐备。
