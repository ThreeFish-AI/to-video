# Stage ⑥ 分镜表生成（skill 规格 · 06）

> Stage ⑥：把逐字稿切「镜」，产出 `script/storyboard.md`——Remotion 场景组件的实现规格。

## 产出结构

1. 头部：与 narration.md 句 id 对齐说明；时长以音频 manifest 实测为准的声明；**本集视觉契约**（色板 hex + 语义映射，与 planning.md 一致）。
2. 每幕一节（对应一个场景组件 `video/src/scenes/P<n><Name>.tsx`），内含分镜表：

| 镜 | 句区间 | 画面 | 动效 |
|---|---|---|---|
| 2-A 章头 | p2-01..04 | 蓝色章节卡…… | 章节转场 |

3. 字幕规范（底部单行、一句一条、字号、与配音同步）。
4. 实现映射：幕 ↔ 组件名对照、公共组件清单（金句卡/章节卡/字幕条/图标集）。

## archify 资产标注规范

用到 archify 图例的分镜，标注本身就是覆盖门的输入（`pipeline.py check` 自动串联
[check_archify_coverage.py](../scripts/check_archify_coverage.py)，刻意不设 flag——可忘带的
flag 即可被静默缩小的检查面）：画面列标注（形如 `·**archify full**：图名 章id+章id`，图名 =
slug 或该图任一章 label）与场景代码 cue 构成**双向对账**的两端——声明未实现即 FAIL、
有 cue 未声明即 WARN。纪律：

- **cue 写法概览**：一个 cue = 章节 id + 锚句 + 可选 `fit`（`stretch` 变速铺满 / `hold`
  原速播完冻结末帧补足 / `trim` 原速超窗截断），落在场景代码 `<ArchifyRecap>` 上。对位原子
  单位是**「一章↔一句」**，不是「一拍（镜）↔一句」：一镜可挂多章分句接力，但每章独立锚定
  一句，且同锚句双 cue 直接 FAIL（锚句唯一 ⟺ 帧窗不相交）。
- **跨实例背靠背（含镜界切换——beat 间无 sceneGap）时，后挂实例必须 `lead={false}`**：
  入场弹簧与角标淡入的抑制判定（enters）只在单实例内生效、管不到跨实例接缝——不显式关掉，
  前例末帧冻结 / 换章收尾段会被入场动画再吃一次，读作卡顿。首段与空窗后重现的实例保持默认
  `lead`，否则整框以全不透明一帧瞬现。
- **storyboard 全文禁出现覆盖门计数的字面串（画面列标注行本身除外）**：门的计数断言按
  **全文**统计 `archify (full|inset)` 命中数、解析只取画面列——表头警示语 / 动效列 / 备注散文
  里多写一处即计数恒不匹配 ⇒ FAIL（ISSUE-191 实测：表头警示语误写该字面量，当场红门）。
  散文一律写「全屏独占 / 画中画」。
- **引用句 id 前先对照 narration 实存句集**：跳号句（id 不存在）上建的嵌套窗，tsc 与覆盖门
  全放行、渲染期才抛「未找到句 id」（ISSUE-190 的 p1-23 即此形态）。非 cue 的 `at()`/`dur()`
  句引用现由 `pipeline.py check --check-scenes` 做存在性 FAIL——该门需显式带 flag，不带即不查。
- **sidecar 图型词表以录制器 `--type` 为准**：`architecture / workflow / sequence /
  dataflow / lifecycle`——archify 出图词汇里的 **state 型在本管线映射为 lifecycle**。回填
  `video/public/archify/<slug>.json` 顶层 `type` 时按此词表写：越表值会在录制前置预检
  （`record_archify_all.py`，dry-run 与真录共用）直接 FAIL（上游 ISSUE-201 实证：type=state
  曾拖到建图完成数小时后的录制中段才被 argparse 拒绝、退出码 2）。

完整判据（覆盖度 / 丰富度 / 匹配度三维 + 防少算计数断言）以该脚本模块 docstring 为 SSOT，
本节是分镜侧摘要——改判据先改 docstring，再同步这里，两处表述须同构。

## 切镜规则

- 一「镜」（beat）= 一段连续句 id（2–8 句）共享同一主画面；镜内动效随句推进。逐字稿幕内已按空行分好 beat（⑤ 成文优化产物）时，镜界优先沿空行切。
- 句 id 区间必须**覆盖该幕全部句子、无交叠无遗漏**（组件内以 `beatWindow(sentences, sceneFrom, from, to)` 取窗口）。
- 每镜「画面」写清：主体元素、布局、色彩（用契约色名）、出现的角标；「动效」写清：入场方式、随句节奏的推进（生长/高亮/计数）。
- **画面文字不复述口播**：每句口播已由 frozen Subtitle 烧录在底部字幕带，金句卡 / 清单条 / 判词条若与该句逐字相同，观众看到的是上下两层同一句话。画面文字只放字幕给不了的东西——关键词、数字、标签、结构（如口播「门槛跟着风险走——够不上就升级」→ 画面「门槛随风险 · 升级留人」）。执法：`pipeline.py check`（`all` 同链；缺省执法，无需 flag；en 版对英文字幕同样执法）逐字重合即 FAIL（判据见 `check_script.py` 的 `check_caption_duplication` docstring，RSI-007）；章节标题卡、同幕回扣等刻意复述，在该行或上一行注 `caption-dup-ok: <理由>` 逐处豁免，降为 WARN 留痕。
- 风险/反转段显式标注色调切换（如「画面转红调」）。
- **画面感与过程具象化四定式（对齐 C 型 01 §七「素材映射」，让小白被动收看即懂，RSI-032）**：
  1. **全景坐标先行（Map-First Anchor）**：每幕首镜或换层镜先亮出全片架构全景坐标（优先挂已录制的 `archify` 引导图或恒定视觉锚），高亮当前所讲环节，消除局部迷航；
  2. **机制必演单步流转（Animated Worked Example）**：讲核心机制时**严禁只摆静态方框**；画面须取 1 个具体输入值，随句边界 `rel(beat, '句id')` 动态演示「输入进入 → 组件内部状态变换 → 输出」的逐拍轨迹；
  3. **反例必演消融对比（Counterfactual Ablation Contrast）**：讲破坏性实验或反直觉设计时，用左/右或前/后同屏对比——警示红 `#FF5C5C` 演「拔掉该组件后在哪一步崩溃 + 实测退化值」↔ 确认绿 `#7ED321` 演「机制在位时如何拦截」；
  4. **数字必带基线标尺（Baseline-Anchored Bar）**：实证数字严禁原样搬 Markdown 多列大表，一律化为「基线 vs 本机制」的动态增长条（`useCount`）+ 工况角标，口播直讲「一句话读法」；
  5. **开篇首镜视听合力定式（Visual Hook on 0-A / p0-01）**：开篇第一镜承担前 3–5 秒锁死注意力的核心使命，画面必须与口播「这是 XXX ……」形成强视听合力，第一秒呈现高反差核心意象或动态冲击，严禁静止文字卡或空洞素材，奠定全片视觉基调并放大开篇钩子的留存威力。
- 采用 [建模手册](MODELING-PLAYBOOK.md) 条目的镜，在「画面/动效」列标注〔M-xxx〕——策展复盘按此计数（至迭代：每次复用都是一次再验证）。
- **顶部安全带 y<56 由章节条占用**（见 [08-remotion-implementation.md](./08-remotion-implementation.md)「顶部章节进度条」）：
  各幕画面内容 y≥56 起；SceneTag 维持 top:64 不变。

## 验收

- 逐幕核对句 id 连续性（首个 beat 起于本幕第一句，末个 beat 止于本幕最后一句，相邻 beat 区间无缝衔接）；
- 每镜画面均可在 Remotion 用现有公共组件 + 少量定制实现（不出现无法代码化的素材需求）；
- 定稿前按 [05 成文优化](./05-prose-refinement.md) 第七节过一遍画面 / 动效列的写法（现在时、只写看得见的、旁白讲画面给不了的）；句区间与各类机器可读标注不动。
